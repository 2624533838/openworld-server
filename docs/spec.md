# 2D 开放世界 RPG 服务器— 项目规格

## 定位

一个人能完成的开放世界 RPG 服务端微缩版。真实开放世界RPG服务端是几十人团队做的分布式系统，本项目的目标**不是复刻原神**，而是把它的核心概念——**分线、AOI 视野、状态同步、数据持久化**——在一个人能完成的尺度下完整跑通，。

## 架构

```
客户端（Java 2D）
   │ 原生 TCP + protobuf
   ▼
网关（gateway）：连接管理 / 鉴权 / 转发
   │
   ▼
逻辑服（game server）：AOI / 状态同步 / 玩法 / 持久化
   │
   ├── Redis（在线热数据）
   └── MySQL（离线存档）
```

> 第一版网关和逻辑服可先合并成单进程，第二版再拆。

## 技术栈

- **服务器（C++20）**：Asio（跨平台网络）+ 自实现 Reactor + protobuf + spdlog + GoogleTest
- **持久化**：内存权威 → Redis 热数据 + MySQL 冷存档，定时落盘
- **客户端（Java）**：，硬约束为「原生 TCP + protobuf」，框架自行决定
- **构建**：CMake（依赖用 FetchContent / vcpkg 管理）

## 核心概念 → 项目模块对照

| 开放世界RPG概念 | 项目实现 |
|---|---|
| 分线/分块 | 大世界切成 zone，玩家跨块切换 |
| AOI 视野 | 九宫格，只同步附近玩家 |
| 状态同步 | 移动/属性服务器权威 |
| 数据持久化 | 玩家数据存 Redis/MySQL，掉线不丢档 |
| 分布式 | 网关 + 逻辑服拆分 |

## 迭代计划（5 周）

### 第 1 周：地基
- [ ] CMake + Asio 环境搭好
- [ ] echo 服务器跑通
- [ ] Reactor 模型（事件循环 + 非阻塞 IO + 连接管理）

### 第 2 周：协议 + 粘包拆包
- [ ] protobuf 编解码接入
- [ ] 粘包/拆包（长度前缀）处理
- [ ] 消息时序表联调（假客户端）

### 第 3 周：地图 + AOI + 状态同步
- [ ] 分块格子地图
- [ ] 玩家移动 + 服务器权威校验
- [ ] 九宫格 AOI 广播

### 第 4 周：持久化 + 网关拆分
- [ ] 玩家数据 Redis/MySQL 分层落盘
- [ ] 网关 + 逻辑服拆分（可选，先单进程）
- [ ] 心跳 + 断线重连

### 第 5 周：工程化
- [ ] GoogleTest 单测（Reactor/粘包/AOI）
- [ ] 压测（模拟 N 个假客户端）
- [ ] README + 整理
